A dependency bump should not need the paperwork of a new feature. In CodeCrew, until this week, it did.

CodeCrew is our open-source framework for running a crew of AI coding agents on plain GitHub: each agent has its own identity, none approves its own work, and every decision stays on the record next to the code.

Version 2.0 asked every project using it to move to a new layout. Those projects, a one-person blog among them, reported the same thing: the process was the same size whatever the change. Version 2.1, out on 24 September, lets small work stay small:

• A requirement the team decides to drop can be marked as dropped, linked to that decision, instead of blocking the milestone from closing.

• A change a tool produced, like a dependency bump, travels as one reviewed pull request, without a feature's plan and sign-off.

• One command brings a project's agent instructions up to date, and refuses to overwrite any the project wrote itself.

• Agents check they are running the right version before they start, then upgrade or ask a human, never mid-task.

Nothing a 2.0 project already does breaks, and there is nothing to migrate. Fittingly, the release that added a way to drop requirements dropped none: its own record says the command was not used live.
